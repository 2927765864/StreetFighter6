# 屏幕震动：每趟帧数对齐

屏幕震动面板默认开启「每趟帧数对齐」，FOV 和相机局部位移均适用。
每趟指一个转折点到下一个转折点之间的帧间隔，不把两端画面重复计数。

- 每次有效显示推进一个震动帧；暂停重绘不推进。
- 触发位置阶跃的首张画面先显示拉开的位置，下一张才开始回弹。
- 初始速度为零、参数保持不变、没有后续冲击或限幅打断时，第一趟与后续每趟严格等帧，摆幅逐趟衰减。
- 若还有速度冲量或先前震动的残余速度，开头可能是未完成的一趟；后续完整往返仍采用整数帧周期。新冲击会叠加状态，不能要求跨冲击的移动段也等长。
- 阻尼比达到或超过 1 时不往返，面板显示「不往返」。

## 参数与取整

采用固定 60 帧作为节奏标定。正常倍速下，每趟帧数为：

`N = max(2, round(60π / (ωn × sqrt(1 − ζ²))))`

开启跟随游戏倍速时，先把倍速乘入分母，再取整。至少两帧，保留端点间的一个中间采样。
调整有效频率使每趟恰好为 N 帧，保持原阻尼比。面板直接显示 N。
因此小幅调整频率可能仍停在同一个帧数档位；这是有意的整数帧取整。
输入频率支持面板的 4–120 rad/s，不再暗中截断到 60。

例如 ωn=90、ζ=0.46、初速度为零时，每趟 2 帧。
将触发画面记为第 0 帧，则转折点出现在第 0、2、4、6……帧。

## 时间取舍

锁帧模式优先保证实际绘制的移动帧数，掉帧时不追赶墙钟时间。
所以较低显示帧率会让震动在现实时间中变慢，较高显示帧率会让它变快；以项目默认 60 帧显示为基准。
暂停期间重复显示同一画面的刷新不算移动帧。
关闭「每趟帧数对齐」可按实际时间推进，此时不保证每趟显示帧数相等。

## 实现与验证

弹簧采用解析解，避免欧拉积分的周期误差。临界和过阻尼也采用稳定的解析推进。
旧存档自动开启锁帧；显式关闭可以保存。旧 substeps 字段仅用于存档兼容，面板不再展示无效的积分子步设置。
单帧时间上限仅影响按时间推进模式。

`app/tests/motion/frameAlignedShake.test.ts` 检查首帧、连续往返帧数、FOV 与位置实际相机输出、衰减、暂停/单步、不规则帧时长、倍速、冲量叠加、旧存档和不振荡的阻尼。

## 镜头动态模糊

「镜头强度」作用于全画面，包括角色与场景；角色自身动作的模糊另由移动/攻击强度控制。
镜头模糊取相邻有效帧之间的震屏变化，不能取当前震屏偏离原位的距离。
因此回弹经过原位时仍可有明显模糊，而相机停在偏移位置不动时不应继续模糊。

位移与 FOV 都纳入计算，前后移动与 FOV 变化产生随屏幕位置变化的缩放拖影。
保留上一帧相机局部震屏与投影变化，将其应用到当前未震动相机，排除普通跟镜。
逐帧暂停时保留上一有效帧的模糊，下一次单步再更新。
全屏速度场使用当前像素的真实几何深度重新投影，角色、地面与背景各用自身的距离。相机位置移动时，同一屏幕位置的近处表面比远处表面产生更大的运动；纯 FOV 缩放不人为附加距离倍率。
绘制后层角色后保存场景/后层角色深度，绘制前层角色后保存前层深度，然后按前层覆盖优先选择可见表面，避免角色分层和前景特效清空深度后丢失背景。沿用已有几何绘制，仅增加深度复制，不增加场景重绘；画中画不覆盖主画面的深度快照。
不写入深度的半透明粒子和屏幕光效仍随底下的可见表面计算模糊，因为混合像素没有唯一几何距离。保留原有角色遮挡次序。
后期移动足够小时仍受 0.75 像素死区影响，帧数相等不意味着每帧模糊强度相等。
