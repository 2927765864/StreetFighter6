# 打击特效编辑器：已敲定需求整理

> **状态**：对话敲定、待你核对（2026-08-26）  
> **用途**：把界面改造要做成什么写清楚，用白话，不写实现步骤。  
> **关系**：落实后应回写 `docs/hit-vfx-consensus-v0.md`（尤其「独立编辑页」与「火花光照是否独立元素」）。  
> **入口页**：现有 `/hit-vfx.html` 要改造成完整图形化工具，而不是现在这种「下拉框 + 数字框」凑合面板。

---

## 1. 一句话目标

做一个**完整、好看、好用**的图形化特效编辑界面：能管多套完整配方、配方里能分组、组里能增删改元素；支持重命名、复制粘贴、保存、删除；还能把单个元素存成预设，之后随时套用。

---

## 2. 结构怎么理解

你要的是**两层含义一起有**：

| 名称（白话） | 是什么 | 例子 |
|--------------|--------|------|
| **配方** | 一整套打击特效配置 | 「未格挡受击」「格挡成功」 |
| **分组** | 某一配方内部的整理用文件夹 | 「主火花组」「扬尘组」 |
| **元素** | 真正播放的一块画面内容 | 一颗火花、一股扬尘、一串汗珠 |

**结构树固定为三层：**

```
配方
 └─ 分组
     └─ 元素
```

左边（或主工作区）用这棵树选中对象；右边（或下方）调当前选中项的参数。

---

## 3. 配方（整套特效）要能做什么

| 操作 | 要求 |
|------|------|
| 新建 | 能新建一整套配方 |
| 重命名 | 能改显示名称 |
| 复制 | 能复制成另一套新配方 |
| 粘贴 | 粘贴出新的一套配方（与复制配套） |
| 删除 | 能删；**必须弹窗确认**后再删 |
| 保存 | **写入项目配置**，下次打开工程还在（进仓库那套） |
| 选用 | 能指定哪套用于实战「未格挡」、哪套用于「格挡」 |
| 编辑中切换 | 能选当前正在编辑的配方，预览跟它走 |

**说明：** 复制粘贴做到「整套配方」这一层即可；**不必**单独复制「分组」。

---

## 4. 分组要能做什么

| 操作 | 要求 |
|------|------|
| 新建空分组 | 先建空文件夹，再往里加元素 |
| 重命名 | 改分组显示名 |
| 删除 | 删分组时**组内元素一起删**；**必须弹窗确认** |
| 拖拽整理 | 能把元素拖到别的分组 |
| 整体开关 | 不删内容，一次关掉/打开整组播放 |

**不做（本轮）：** 分组本身的复制粘贴。

---

## 5. 元素要能做什么

| 操作 | 要求 |
|------|------|
| 新建 | 在当前分组里新建；选类型后出现可调参数 |
| 单独调整 | 每个元素有自己的参数面板，改完预览立刻能看出差别 |
| 重命名 | 改元素显示名 |
| 复制 / 粘贴 | 支持单个元素复制粘贴（可贴到当前或目标分组） |
| 删除 | 能删；**必须弹窗确认** |
| 开关 | 可单独启用/禁用（不影响同组其他元素） |
| 存成预设 | 见下一节 |

### 5.1 新建时可选的元素类型

本轮**可以新建**的类型只有这些：

1. **火花**
2. **附带小粒子**
3. **扬尘烟雾**
4. **汗水飞溅**

### 5.2 关于「火花光照」（重要变更）

- **不要**再把「火花光照」当成树上可新建、可单独存在的元素。  
- **亮度 / 光照相关参数写在「火花」自己的参数里。**  
- 预览与实战仍要能照亮假人（以及同组其他特效，若现有能力保留），但编辑时只看到「火花」这一行。  
- **旧数据迁移**：若已有独立的「火花光照」元素，打开/加载时**自动并进对应火花的参数**，树上**不再单独显示**。

---

## 6. 元素预设

| 项 | 要求 |
|----|------|
| 存成预设 | 选中某个元素 → 存为预设（进预设库） |
| 新建时选用 | 新建元素时可从预设库挑一个套用，再微调 |
| 加到任意组 | 能把预设加进任意配方的任意分组，跨组复用 |
| 保存位置 | 与配方一样，**写进项目配置**，重开仍可用 |

预设管的是**单个元素模板**，不是整套配方。

---

## 7. 保存怎么理解

- **正式保存**：写入**项目配置**（下次打开还在，可进仓库）。  
- 本轮**不以**「只存浏览器临时数据」作为主完成标准。  
- 现有「存本地默认 / 导出 shipping」若保留，须服务「进项目配置」这一目标，不能只剩临时本地一份。

---

## 8. 预览与调试（沿用已有共识，编辑器必须仍具备）

这些不是新发明，但图形化改造后**不能丢**：

- 一键重放同一次击中预览  
- 低速 / 逐帧查看  
- 锁定随机种子（同一次重放一致）  
- 预览未格挡 / 格挡路径  
- 预览头 / 胸 / 腿高度  
- 预览轻 / 中 / 重力度  
- 独立页：有场地与光照、有可被照亮假人、**无对战角色**  
- 改完的配方与训练场命中用**同一套数据**

---

## 9. 界面品质与语言

| 项 | 要求 |
|----|------|
| 完成标准 | **管理能力齐全**，并且界面要**明显好看、专业**，不能只是功能堆上去 |
| 语言 | **中文为主**（按钮、菜单、提示） |
| 形态 | 独立编辑页专用 UI；不是训练场侧栏临时凑出来的控件 |

### 建议布局（待你确认细节时可改，方向如下）

1. **左**：配方 → 分组 → 元素 树 + 新建/复制/删除等操作  
2. **中**：3D 预览（假人 + 特效）+ 重放 / 步进 / 速度等  
3. **右**：当前选中对象的参数（配方级 / 分组级 / 元素级随选中切换）  
4. **顶或底**：保存、实战选用哪套配方、预设库入口等

---

## 10. 删除与安全

- 删**配方**、删**分组**、删**元素**：一律**先弹窗确认**，确认后才真正删除。  
- 本轮**不做撤销**（不做「删了还能 Ctrl+Z」）。

---

## 11. 本轮明确不做

- 分组的复制粘贴  
- 把「火花光照」继续做成可新建的独立元素  
- 只依赖浏览器本地、不进项目配置的主存档路径  
- 音效、镜头震动、角色闪白、扣血数字等（仍按打击特效共识排除）  
- 本轮不为「好看」另做一套假预览；预览必须接真运行时

---

## 12. 和现状的差距（方便对照）

现在的 `/hit-vfx.html` 大致是：下拉选配方/元素、改数字、重放、存本地/导出。  
**缺或很弱的：**

- 完整三层树形管理  
- 图形化新建配方 / 分组 / 元素  
- 重命名、复制粘贴  
- 拖拽换组、分组总开关  
- 元素预设库  
- 专业分区布局与观感  
- 火花光照收进火花参数并自动迁移旧数据
