## 0. 一句话与产品形态（✅）

在**训练场主场景**进入「框图编辑模式」，用来把**角色动画**与**判定框**对齐（与对战共用舞台、灯光、相机、双人表现）。

交互形态对齐**剪辑软件**：主画面为训练场同款；叠层时间线与工具条。拖进度、播放、循环时，**动画与框必须按同一逻辑帧同步**。

| 是 | 不是 |
|----|------|
| 自用、图形化的框校准与自定义工具 | 另开一套简陋单人预览页当正式画面 |
| 表数据驱动的预览 + 可写回改动层 | 只读查看器 |
| 侧面校对框是否贴合身体（同训练场相机） | 完整 3D 建模式镜头编辑 |
| 服务本仓库隆（Ryu）训练场数据 | 多角色公开发布的通用中间件产品 |

**主要用户（✅）**：作者本人——校准 MMDK/转换表偏差，并允许完全自定义框。

## 1. 编辑对象（✅）

### 1.1 框种类（统一编辑）

| 种类 | 白话 | 调试色（时间线条 + 画面） |
|------|------|---------------------------|
| 攻击框 | 能打到对方的区域 | 红 |
| 受击框 | 自己会被打中的区域 | 绿 |
| 推挤框 | 站位互相顶开的区域 | 黄 |

三类在**同一编辑器**中编辑，不拆成三个互不相通的工具。

### 1.2 覆盖范围

| 范围 | 共识 |
|------|------|
| 出招过程中的框 | ✅ 要做 |
| 站立 / 蹲下待机身体框 | ✅ 要做（与出招同工具；可用模式切换，勿与出招时间线语义混成一团乱轨） |
| 飞行物框（如波动） | ⬜ **点名延后**：目标保留，**当前可不实现**；延后原因：先闭环角色身上框 + 时间线 + 双文件层 |

### 1.3 角色范围

| 项 | 共识 |
|----|------|
| 第一批数据 | **仅隆（Ryu）** |
| 架构 | 允许日后扩角色；**不要求**本共识交付时做多角色切换 UI |

## 2. 痛点与必须同时具备的能力（✅）

当前主要痛点：

1. 框相对身体 **位置 / 大小** 不对  
2. 框 **出现 / 消失的帧** 不对  

因此下列能力同属完整目标（禁止只做其一）：

| 能力 | 说明 |
|------|------|
| 时间线 scrub | 拖进度条，动画与框逐帧同步 |
| 播放控制 | 播放 / 暂停 / 上一帧 / 下一帧 / **循环播放整招** |
| 画面改框 | 点选框；拖整体改位置；拖边改宽高 |
| 数字精修 | 选中后可用数字改坐标与宽高 |
| 改寿命 | 在时间线上调整框的起止帧（出现 / 消失） |
| 新建 / 删除 / 改种类 | **不完全依赖**外部表；可完全自定义 |
| 撤销 / 重做 | 含常见快捷键语义（如 Ctrl+Z） |
| 自动保存改动层 | 改完写入「改动文件」，不必每次手动点保存 |
| 改动标记与恢复 | 见 §4 |

---

## 3. 时间与几何语义（✅）

| 项 | 共识 |
|----|------|
| 段内形状 | 一个框在「存活的那一段帧」内 **形状不变**（整段共用一个矩形） |
| 可改内容 | 该段的 **from / to**，以及该段共用的 **位置与宽高**；种类可改 |
| 逐帧变形 | **不要求**同一框在段内逐帧插值变形；需要对齐不同形状时 → **拆段或新建另一段** |
| 帧权威 | 与 ADR-001（60 Hz）、ADR-003（招式帧索引）一致；画面 scrub 跟 **逻辑帧** |
| 盒约定 | 与 ADR-002 一致：`x,y` 为中心，`w,h` 为全宽高；面向相对本地坐标 |

## 4. 数据：原始层 + 改动层（✅）

| 套 | 规则 |
|----|------|
| **原始文件** | **永不被编辑器改写**；用于恢复默认 |
| **改动文件** | 编辑结果落盘处；**游戏实际运行优先采用改动层**（有改动则用改动，否则用原始） |

### 4.1 恢复与可见性

| 能力 | 共识 |
|------|------|
| 列表标记 | 能看出 **哪些招（及待机相关项）已被改过** |
| 单招恢复 | **一键**将某一招全部恢复为原始（清除该招改动） |
| 全局恢复 | **一键**清空全部改动，回到出厂原始 |
| 单框级恢复 | ⬜ 未在对话中定为必做；不阻塞上述三项 |

### 4.2 存储形态（✅ · 2026-08-21 方案锁定）

采用 **方案 A**：改动文件与原始 **同结构整文件**，另目录存放。

| 项 | 约定 |
|----|------|
| 招式改动 | `app/public/data/overrides/moves/<moveId>.json` |
| 姿态改动 | `app/public/data/overrides/systems/ryu_stance_boxes.json` |
| 清单 | `app/public/data/overrides/manifest.json`（标记哪些已改） |
| 加载 | `override` 存在则用，否则用原始 |
| 恢复 | 删除对应 override（或清空全部） |

**不采用**仅存补丁再合并（方案 B）作为主路径。  
硬约束不变：原始只读、运行时优先改动层、可恢复。  
依据：`docs/plans/ai-execution-plan-box-editor-v0.md` §0 L1–L2；调研建议恢复=删文件。

## 5. 画面与交互（✅）

| 项 | 共识 |
|----|------|
| 镜头 | **与训练场主场景同一套战斗相机**（侧面） |
| 自由 3D 转镜头 | **不做**（非建模工作台）；编辑模式不启 lightOrbit 当主预览 |
| 对手试打验证 | **不要** |
| 双人表现 | **要**：P1 播当前招；P2 **同一招、同一逻辑帧、朝向相反**（镜像对照）。P2 **不是**可打试打木桩 |
| 画框 | **只画当前编辑侧**（默认 P1）；P2 只播动画不画框 |
| 时间线条 | 框以 **红 / 绿 / 黄** 色条映射存在区间 |
| 入口 | **训练场主页框图编辑模式**（叠层 UI）；**删除**独立 `/box-editor.html` 正式入口 |

待机 vs 出招（✅）：**同一编辑模式内切换**（出招 / 站立待机 / 蹲下待机）；切换时清空选中。  
依据：`docs/plans/ai-execution-plan-box-editor-main-scene-v0.md`；原独立页方案废止。

## 6. 明确不做 / 点名延后（✅）

| 项 | 态度 | 原因 |
|----|------|------|
| 飞行物框编辑 | **延后** | 先闭环角色身上框 + 时间线 + 双文件 |
| 对手参照 / 实战试打 | **不做** | 专注自身动画与框对齐 |
| 自由旋转缩放式 3D 编辑镜头 | **不做** | 侧面校对足够 |
| 多角色切换 UI（交付时） | **不做** | 第一批仅 Ryu；架构可扩 |
| 用「第一版只做 scrub」等拆目标 | **禁止** | 总共识 §0 |

## 7. 与现有系统的边界（✅）

| 边界 | 共识 |
|------|------|
| 对战逻辑 | `app/src/combat/**` 仍 **禁止**依赖 Three；编辑器 UI/预览可走 `render` / 独立页 |
| 运行时读表 | 对战仍读本地表；接入 **改动层优先** 的加载规则 |
| MMDK 原始 dump | `private/mmdk/**` 不进公开分发；编辑器不直接改 private dump 作为运行时权威 |
| 调试面板现有数字改框 | 可作过渡；**本共识的完整目标是独立编辑页**，不是永久用 lil-gui 数字条代替 |

---

## 8. 成功时的样子（✅）

- 打开独立框图编辑页，选中隆的某一招或待机模式。  
- 时间线上可 scrub / 播放 / 循环；每一逻辑帧上，角色姿势与当时应存在的红/绿/黄框一致。  
- 可拖框、改数字、改起止帧、新建与删除框、改种类；有撤销重做；改动自动进入改动层。  
- 列表能看出改过哪些；可单招或全局恢复原始。  
- 回到训练场/对战时，运行时使用改动后的框数据（原始文件仍在、可恢复）。  
- 飞行物框可尚未实现（已点名延后）；其余 §2 能力不得缺项冒充完成。
