本文件只回答：**格挡（防住）要做什么、不做什么**。  
不写排期与文件树冲刺。  
**不格挡被打中**（干挨）仅定义边界；分部位受击动画仍延后。

---

## 0. 范围一句话

对手被打到分两种：

| 路径 | 本阶段 |
|------|--------|
| **格挡（防住）** | ✅ 完整做：判定、硬直、顿帧、推开、站/蹲、`GRD_*` 动画族 |
| **不格挡被打中** | 仅当「姿势防错」时走出此路径；**分部位挨打动画延后**（可占位） |

术语：用户口中「补个档」= **不格挡被打中**（已对齐）。

---

## 1. 段位命名（✅ · 跟官方字母）

表与代码使用 **官方 H / M / L**（与 Capcom 帧表、FAT `atkLvl` 同义）。本地字段可用 `guard: "high"|"mid"|"low"`，但语义必须如下，**禁止**和玩家口语「上中下」混用而不加说明：

| 存盘 / 官方 | 意思 | 站防 | 蹲防 |
|-------------|------|------|------|
| **H** / `high` | 两边都能防 | ✅ | ✅ |
| **M** / `mid`（含过顶；`midHigh` 视同须站防类） | 必须站着防 | ✅ | ❌ → 算没防住 |
| **L** / `low` | 必须蹲着防 | ❌ → 算没防住 | ✅ |

对照：FAT 中 `Collarbone Breaker`（`6MP`）为 **M**；本地若仍为 `high` 须在实现前纠正数据（属本共识范围）。

社区 FAT 表可作 **段位与 onBlock 对照**；不覆盖下一节硬直权威。

---

## 2. 数字权威（✅）

| 字段 | 权威 | 说明 |
|------|------|------|
| **blockstun** | **MMDK HIT_DT** 防住侧 `HitStun`（`common[1]`） | 与当前转换管线一致。例：5LP = **13**（非社区表 9） |
| **hitstop（防）** | MMDK 防住侧 `HitStop*` | 已写入 `hitstopOnBlock` |
| **防御推开总量** | MMDK 防住侧 `MoveDest.x` × 单位换算 | `blockPushbackTotal`；与攻击 Place **分通道** |
| **advantage.onBlock** | 可保留公开/4rays 值作对照 | 不以社区 blockstun 反推覆盖 MMDK |
| **hitstun / 命中推开** | MMDK 命中侧 | 干挨路径用；动画仍延后 |

已知：社区 FAT `blockstun` 对大量普攻 ≈ **MMDK − 4**。本阶段 **不改用** FAT 硬直；FAT 仅对照与纠段位。

**防推开逐帧曲线**：公开渠道无完整集 → 本阶段用 **总量 + 在硬直（或 MoveTime）内分配**；不阻塞验收。  
**进攻 Place**：有曲线用曲线；全 0 的招保持可审标记，不假装已有位移。

## 3. Dummy / 「真格挡」规则（✅ · 升级原 §4.7）

原「P2 全程真格挡、打上即防住」**细化为**：

| 项 | 共识 |
|----|------|
| **模式** | Dummy 可切手动 **站防 / 蹲防**（已有模式保留并验收） |
| **姿势正确** | 段位 vs 站蹲匹配 → **强制防住**（无需模拟真人按后；训练验收用） |
| **姿势错误** | 站防接下段 / 蹲防接过顶等 → **没防住**，走被打中结算 |
| **被打中表现** | 分部位动画 **延后**；本阶段允许 **可见占位**，但逻辑须区分防住 / 没防住 |
| **投技** | 不可防；仍按既有延后/简化 |

---

## 4. 防住结算流水线（✅）

红框碰到可打中的绿框且防守方处于防姿态时：

1. 读攻击 `guard`（H/M/L）与防守 **当前站/蹲防**  
2. 不匹配 → 没防住（§3）  
3. 匹配 → 防住：  
   - 双方 **hitstop**  
   - 防守方进入 **blockstun**（MMDK 数）  
   - 应用 **防御推开**（独立通道）  
   - 伤害：**本阶段防住削血不做**（0）  
4. 选并播放对应 **GRD_*** 片（§5）；**硬直说了算**（§6）

---

## 5. 动画：`GRD_*` 族（✅ · 尽量贴近原作）

| 项 | 共识 |
|----|------|
| **目标** | 尽量接上现有约 45 个格挡相关 glb（`guard` 覆盖族） |
| **做法顺序** | **先摸清命名规律**（站/蹲 × 高低 × 轻重等）→ 再批量映射逻辑 ID；禁止无表瞎接 |
| **最低可见** | 映射完成前，至少站防/蹲防能区分；缺片须 **可见占位** |
| **资源位置** | 以 `ryu-anim-glb-coverage` / `ryu-logic-to-glb-map` 为索引，映射表落 action-tables |

Drive 防 / 完美格挡片 **不接**（§7）。

---

## 6. 硬直 vs 动画 vs 站蹲切换（✅）

| 项 | 共识 |
|----|------|
| **时长** | **硬直说了算**。硬直未结束则保持格挡态（循环或定格末帧）；不因动画片播完而提前结束硬直 |
| **硬直中改站/蹲** | **允许**。下一击按新姿势结算；必要时重选 GRD 片 |
| **硬直结束仍在防** | **保持防姿待机循环**；松手（或 Dummy 离开防模式）再回普通站/蹲待机 |

---

## 7. 明确不做（✅ · 本阶段）

- 不格挡时的 **分部位** 挨打动画（晃、击飞等精做）  
- **接近防**（出招前半即抬手的姿势与框）  
- **Drive 防 / 完美格挡** 及 Drive 条联动  
- **防住削血（chip）**  
- **空中格挡**（SF6 本身不能空防）  
- 用社区 FAT **覆盖** MMDK `blockstun` 权威  

（与 `consensus-design-v0.md` §4.9 延后清单一致并收紧本阶段边界。）

## 8. 验收句（可检查）

1. Dummy **站防** 能防住 H；**蹲防** 能防住 L；**蹲防接 M / 站防接 L** 记为没防住。  
2. 防住时有真实 **顿帧、blockstun、防御推开**；防住伤害为 0。  
3. `blockstun` 与 MMDK HIT_DT 防住 `HitStun` 一致（抽测 5LP=13 等）。  
4. 硬直期间动画不抢时长；硬直中切换站/蹲后，下一击段位判定跟新姿势。  
5. 硬直结束仍防 → 防姿循环，而非闪回普通待机。  
6. `GRD_*` 命名规律文档化后，应接片已映射；未映射有占位。  
7. `6MP` 等过顶招 `guard` 与官方/FAT **M** 对齐后方可标该项完成。
