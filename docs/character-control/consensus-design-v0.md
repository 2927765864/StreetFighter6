## 1. 输入机制（✅）

### 1.1 操作体系

- **仅 Classic**（6 键 + 8 向）。
- **不实现 Modern**。
- 默认输入设备：**键盘**；手柄可扩展，语义与 Classic 相同。

### 1.2 每逻辑帧

- 逻辑 **60 Hz** 采样一次（与 ADR-001 一致）。
- 每帧记录：
  - 方向（numpad **1–9**，相对**当前面向**）
  - 六键按下 / 持续 / 松开（实现可简化，但语义上区分边沿与按住）
- 输入先进入缓冲 / 历史，再由状态机决定是否消费。

### 1.3 指令意图类别

识别器应能产生（或预留）以下意图类型：

| 意图类型 | 示例 |
|----------|------|
| 移动 | 走、蹲、跳、66 / 44 dash |
| 普攻 | 5 / 2 / j. + LP…HK |
| 指令普攻 / TC | 6MP、4HP、HP~HK 等 |
| 必杀 / OD | 236P、623PP 等 |
| 超必杀 | 236236P 等 |
| 投技 | LP+LK / 4+LP+LK |
| Drive | DI、Parry、DR、Reversal（可占位，**接口预留**） |

### 1.4 指令识别原则

- **方向历史 + 按钮** 匹配 special / super（步间间隙见 §2）。
- **Dash** 用独立规则，不与 special 混成同一套匹配器。
- **同帧多意图** 用**固定优先级表**裁决；禁止隐式「谁先处理谁赢」。
- 面向翻转时，左右方向与盒一并镜像。

### 1.5 同帧优先级（初表，可后改）

从高到低：

1. Super（资源与状态允许时）
2. Special / OD
3. Throw
4. Drive 系统技（DI / Parry / DR 等，按当前状态是否合法）
5. Target Combo / Chain 后续
6. Normal
7. Dash / Jump / Walk / Crouch

**命中解析**（与输入优先级分开）：

- 同帧 **strike > throw**
- 无无敌时双方 hit → **trade**

## 2. 预输入 / 缓冲（✅）

### 2.1 总原则

- **要做预输入**（对齐 SF6 input buffer 语义）。
- 工程上拆成 **三层**：

| 层 | 作用 |
|----|------|
| **A. Action buffer** | 不可行动期登记下一意图，可行动时执行 |
| **B. Motion history** | 方向序列历史，供 special / super 匹配 |
| **C. Cancel 窗消费** | cancel 窗内合法意图打断当前招 |

### 2.2 默认数值（可配置）

| 配置项 | 默认 | 含义 |
|--------|------|------|
| 标准行动预输入 | **4f** | 多数 link / 硬直结束出招等 |
| Dash / 起身类更宽缓冲 | **7f** | dash、部分 wakeup 相关 |
| 起身 reversal 与 7f 冲突时 | **进配置表审查**，不散落硬编码 | 公开资料口径可能不一致 |
| 指令步间最大间隙 | **约 9f**（可按招覆盖） | 初值 |
| Dash 方向 / 中性上限 | 各 **8f** | 对齐公开 Movement 整理 |

改手感优先改配置 / 表，不改状态机主路径。

### 2.3 行为规则

- recovery / hitstun / blockstun / landing 等**锁定期**可写入 action buffer。
- 进入**可行动**的第一帧按 §1.5 优先级消费 buffer。
- **Hitstop** 期间：位移 / 招式帧可停，**仍须接受** cancel / buffer 输入。
- 存在「必须晚 cancel」的连段：支持不被「尽早 buffer」破坏的策略。
- 已知例外 → **例外表**，不散落 if。

### 2.4 缓冲范围（✅ · 2026-08-13 去「分期」措辞）

| 项 | 共识 |
|----|------|
| 标准 4f + motion 历史 + cancel 消费 | **须完整实现** |
| Dash 7f / 起身更宽（默认 7） | **须完整实现** |
| Screen freeze / DR 冻结与 buffer 相位 | **延后**（依赖 Drive/冻结系统深度；见 §4.7 后置） |

## 3. 动画 / 逻辑状态机与打断（✅）

### 3.1 总原则

- **规则权威 = 逻辑状态 + 本地帧表 / cancel 标志**，不是 3D clip 长度或 Animation Event。
- 动画是**表现层**：跟随 `moveId + localFrame`（可 cross-fade），不反向定义规则。
- 服从总共识 **R2**：不符理想行为时改本地表再贴动画。

### 3.2 必须建模的逻辑状态族

| 族 | 要点 |
|----|------|
| Neutral | stand / crouch / walk；面向 |
| Attack | startup / active / recovery；`localFrame` |
| Stun | hitstun / blockstun；可带 CH/PC 修饰 |
| Knockdown / Wakeup | 倒地、起身（细则可分期） |
| Jump | prejump → airborne → landing recovery |
| Dash | forward / back |
| Throw | startup / active / whiff / tech 结算 |
| Special / Super | 与 Attack 同形或子类；资源消耗 |
| Drive* | Parry / DI / DR / Reversal 等（**可占位**，接口预留） |

### 3.3 招式阶段

- **Startup / Active / Recovery**；startup 计数与项目帧索引约定一致（含 FAF / 第一 active）。
- 命中进入 **hitstop**；输入按 §2 处理。

### 3.4 可打断矩阵（逻辑）

| 当前 | 可被什么打断 | 条件 |
|------|----------------|------|
| Attack（cancel 窗内） | Sp / SA / DI / DR / TC·Chn / Jmp（若表允许） | **逐招表 + 当前帧** |
| Attack（窗外或无旗） | 仅受击或自然结束 | — |
| Hitstun / Blockstun | 一般不可主动出招；可 buffer 至结束 | 系统技按表 |
| Prejump | 可 special cancel；不可 DI/Parry | 帧数进表（多数 4f）；见 §3.13 |
| Dash | 前 dash 前段可进 Parry 等（按表） | 其余高度锁定 |
| Landing | 按落地规则分帧可行动 | §3.13：空挥第 2–3 帧可接地面攻击 |
| 动画 clip | **永不**单独授权打断 | 只跟逻辑 |

### 3.5 Cancel 表

- **按招、按帧 / 区间**；禁止「只要 active 就能全 cancel」。
- 能表达公开表常见语义：**C / Sp / SA / Chn / TC / Jmp** 等。
- 调试 H2：状态名、localFrame、是否在 cancel 窗。

### 3.6 与动画边界

- 逻辑切状态 → 表现切 clip。
- 开 / 关 hitbox **以逻辑帧为准**。
- 视觉可插值；**判定与调试框以逻辑为准**。

### 3.7 逻辑帧如何带动画面（✅ · 2026-08-11；§3.7.1 · 2026-08-11）

> 对话确认：游戏 **60 格/秒** 与出招画面 **逐格对应**；不以动画文件自己播完作为**逻辑**收招条件。

| 原则 | 共识 |
|------|------|
| 时间权威 | **逻辑 60 Hz**（ADR-001）。出招锁定段内：当前是第几逻辑格，就显示该格对应姿势。 |
| 出招逻辑总长 | 以**本地招式表**的 `total`（= startup+active+recovery）为准；数字**对齐公开帧数据**后再写入本地（总共识 R2）。例：隆站轻脚（5LK）逻辑 **18f**。 |
| 与动画文件 | 文件时长（例：5LK glb **~48f@60**）可以**长于或短于**逻辑 total。**可行动 / 硬直结束 / cancel 窗 / 判定**只看逻辑，**不**看 glb 是否播完。 |
| 画面取样（锁定段） | 逻辑格与动画时间轴按 **60Hz 前缀对齐**（逻辑第 *f* 格 → 动画约第 *f* 采样），**不得**把整段 glb 均匀压进逻辑 total（避免 48 被压成 18 的「快进截断」观感）。 |
| 待机 | 允许动画 **自由循环**（不强制与某一出招表 total 对齐）。 |
| 多段动作 | 走路 / 跳跃等按**逻辑阶段**切换片段（如起步→循环→结束；起跳→空中→落地）；**每一段内**仍用本段逻辑帧推进画面。 |
| 官方文档 | Capcom **无**公开的「逻辑帧↔引擎动画 API」规范。工程依据：公开帧数据（时间语义）+ 本文件 + ADR；社区引擎文档（如 MUGEN AIR 的 game-tick）仅作结构参考。 |

**否决**：以 3D clip 长度或 mixer 自然播完作为出招 **逻辑**结束条件（硬直/可行动点仍以表 `total` 为准）。

#### 3.7.1 出招逻辑总长 vs 动画残留（可打断尾）（✅ · 2026-08-11）

> 对话确认（5LK 为例）：**完整动画素材帧数 ≠ 逻辑 total**。逻辑结束后，**无更高优先级表现承诺**时应播完素材；**新承诺 / 姿态不兼容**时打断残留。  
> 口语可记：`glb 全长 ≈【逻辑前摇+活性+逻辑后摇】+【动画残留】`。  
> **注意**：表上的 **recovery（逻辑后摇）** 已含在 `total` 内；**动画残留**不是公开帧表里的 recovery，只服务观感。

以站轻脚（5LK）为例（数字随表更新，结构不变）：

| 段 | 长度（例） | 逻辑状态 | 输入 |
|----|------------|----------|------|
| **① 战斗锁定段** | **18f** = startup + active + recovery（表 `total`） | 出招中；判定/硬直权威 | **默认不可打断**。合法例外：表内 **Cancel**（如击中/防住后特 cancel 等；实现可分期）。 |
| **② 动画残留段** | **max(0, animFrameCount − total)**（例 48−18=30f） | **逻辑已可行动**（`canAct`） | 见下方 **打断规则**（不是「有键就打断」）。 |

```text
[==== ① 逻辑锁定 total（例 18f）：默认可取消外不可打断 ====][=== ② 动画残留：条件打断 ===]
|<------------------------ glb / 动画时间轴全长（例 48f@60） ---------------------------->|
         ▲ 可行动点 = total 结束（公开帧）
```

| 项 | 共识 |
|----|------|
| 可行动点 | **仅**表 `total` 结束；**不**因 glb 更长而延长硬直或帧优势。 |
| 残留期间 phase | 逻辑 **可行动**；表现可仍显示该招 clip 尾段。逻辑姿态可已是 squat/stand（hurt 等），与 clip 尾并行。 |
| 取样 | 锁定段与残留段共用 **同一 60Hz 动画时间轴**；锁定 0…total−1，残留 total…末帧。 |
| animFrameCount 来源 | 映射 / 文件名 `_fN` / duration×60 等；若 **≤ total** 则无残留。 |
| Cancel | 发生在 **① 锁定段内**（按 cancel 表）；与 ② 残留打断是不同机制。 |
| 明确不做什么 | 不得把 `total` 改写成 glb 帧数；不得在残留段继续开 hitbox。 |

##### 残留打断规则（✅ · 2026-08-11 · 对话确认）

> 核心：**打断看「新表现承诺 / 姿态不兼容」，不看裸「本帧有没有按键」。**  
> 持续按住与招式 **相同姿态** = **没有新承诺** → **不打断**残留（否则蹲攻按住下会每帧被 crouch 片盖掉，攻击尾不完整）。

**招式姿态族（stance）**：出招时绑定，至少 `stand` | `crouch` | `air`（可由 move 表标注，或由 moveId 约定推断：如 `2*` 蹲系、`5*`/`6*`/`4*` 站系、跳攻空中系）。

**目标姿态**：由当前面向相对方向 hold 推导——按住 1/2/3 → 想 `crouch`；否则地面中立/前/后站姿向 → 想 `stand`（走路见下）。

| 本帧情况 | 是否打断残留 | 之后表现 |
|----------|--------------|----------|
| **兼容保持**：目标姿态 ≡ 招式 stance（例：2LK 残留 + **一直按住下**） | **否** | 继续残留；逻辑可为 crouch；残留结束后进 **该姿态 idle**（蹲 idle / 站 idle） |
| **姿态不兼容**：目标 ≠ 招式 stance（例：2LK 残留中/后 **松开下** → 想站；或 5LK 残留后 **按下** → 想蹲） | **是** | 清残留 → **§3.7.2 姿态过渡**（下蹲/蹲起）；**禁止**瞬切 crouch/stand loop |
| **新离散动作**：出招、跳、冲、**走路**（4/6 位移承诺）等 | **是** | 清残留（及进行中姿态过渡）→ 新状态动画 |
| **受击 / 击倒等** | **是** | 清残留 / 过渡 → 受击表现 |
| 仅 **none** 且 stance 已是 stand | **否** | 播完残留 → 站 idle |

**否决**：

- `if (anyInput) clearTail`（持续蹲会被误判为打断）。
- 逻辑未到 `total` 却因「想播完动画」拒绝可行动；或逻辑已过 `total` 仍禁止走路/出招只为播完 glb。
- 用「持续按住下」去盖掉蹲系攻击的残留尾。
- ~~姿态冲突后直接目标 idle/loop~~（**废止**；见 §3.7.2）。

**示例**

| 操作 | 期望 |
|------|------|
| 2LK，全程按住 2 | 逻辑后可行动；**残留播完** → 蹲 idle（**不再**播一遍下蹲） |
| 2LK，收招后或残留中松开 2 | 可行动后 **打断残留** → **蹲起过渡** → 站 idle |
| 5LK，无操作 | 残留播完 → 站 idle |
| 5LP/5LK 中或后按住 2 | 可行动后 **打断**站系残留 → **下蹲过渡** → 蹲 idle |
| 任意残留中按 6 走路 / 再出招 | **打断** → 走 / 新招 |

##### 前后冲动画残留（✅ · 2026-08-12 · 同 §3.7.1 结构）

> 对话确认：冲刺 **逻辑** 仍 19f / 23f（公开移动表）结束可行动与位移；glb 更长（例前冲 42、后撤 40）时用 **表现残留**，不得把逻辑改成 glb 帧数。

| 项 | 共识 |
|----|------|
| ① 逻辑锁定 | 前冲 **19f** / 后撤 **23f**：phase=`dash`；**逻辑帧 = 位移过程（A=B）**；默认可行动点 = 锁定结束。 |
| 位移曲线 | **非匀速、前重后轻**（公式）：权重 `w_i=(1-t)^p`，`t` 从冲刺开始 0→结束 1，`p` 默认 1.5；再归一使 **Σdx = 公开距离**（1.252 / 0.923）。禁止默认全程匀速。 |
| ② 动画残留 | `max(0, animFrameCount − logicFrames)`；phase 回 idle/crouch 且 **canAct**；继续 60Hz 前缀 scrub 同一冲刺 clip；**残留段 dx=0**。 |
| 取样 | 锁定 + 残留共用时间轴：0…logic−1 锁定，logic…anim−1 残留（与出招相同，**禁止**把整段 glb uniform 压进 19/23）。 |
| animFrameCount | 映射 `frameCount` / 文件名 `_fN`；缺省则 = 逻辑帧（无残留）。 |
| 打断 | 与出招残留同表：**走 / 攻 / 跳 / 再冲 / 受击** 等新承诺打断；同姿态 hold 不打断；松下要蹲 → 姿态过渡。 |
| 否决 | 用 42/40 当逻辑冲刺时长；残留段继续冲刺位移；逻辑总距偏离公开距离。 |

#### 3.7.2 站 ↔ 蹲姿态过渡（必接）（✅ · 2026-08-11）

> 对话确认：仅「站 idle→蹲」「蹲 idle 无攻击→站」时过渡完整不够；**凡逻辑可行动后发生站↔蹲目标变化**（含攻击收招后、残留打断后）均须走过渡片，不得瞬切 loop。

| 项 | 共识 |
|----|------|
| 资源 | 映射 role：`stand_to_crouch`、`crouch_to_stand`、`main`（蹲 idle）；站 idle 用 `idle`。 |
| 状态机 | 逻辑段：`to_crouch` → crouch idle；`to_stand` → stand idle。段长用本地/映射 frameCount；画面 60Hz 前缀 scrub。 |
| 触发 | 当前逻辑姿态与 hold 目标不一致且 `canAct` → 开过渡（先清不兼容攻击残留）。 |
| 同姿态 | 已蹲+按住下 → 蹲 idle/蹲攻残留，**不开**下蹲过渡。 |
| 攻击残留衔接 | 蹲系残留结束仍按住下 → **直接**蹲 idle；站系可行动后要蹲 → **to_crouch**（禁止瞬切 crouch main）。 |
| 可打断 | 过渡中可行动：出招/跳/冲/走打断过渡；反向 hold 可改为反向过渡。 |
| 判定 | `to_crouch`/蹲 idle：逻辑蹲；`to_stand` 期间仍 crouch 受伤框至过渡结束（简化；与姿态框表一致后可再细化）。 |
| 否决 | 以 `crouch`+`main` **作为站→蹲唯一路径**；直接 loop 冒充下蹲/蹲起。 |

```text
stand_idle ──(要蹲)──► to_crouch (stand_to_crouch) ──► crouch_idle
crouch_idle ──(要站)──► to_stand  (crouch_to_stand) ──► stand_idle
攻击收招后要蹲：清站残留 → to_crouch → crouch_idle
蹲攻残留完仍蹲：→ crouch_idle（无 to_crouch）
```

### 3.11 表现溶图（冻旧 + 溶新）（✅ · 2026-08-11）

> 对话确认：走/停已有软切；攻击收招后接移动生硬，根因是攻击片不在软切策略内。采用 **方案二：冻旧姿势 + 与新动作交叉混合（crossfade）**；做成 **同一套表现机制 + 分情况时长表**，不做成「全局一个时长自动互溶」。

#### 3.11.1 机制（通用）

| 项 | 共识 |
|----|------|
| 做法 | **冻旧 + 溶新**：切换瞬间把 **旧姿势定格**；新动作按自身规则推进（走逻辑帧 scrub / 待机循环 / 攻击 60Hz 前缀等）；在交叉时长内旧权重 1→0、新权重 0→1，两段 **同时** 影响骨架。 |
| 时长含义 | **权重交叉的墙钟（或等价）时长**；`0` = 硬切。 |
| 与逻辑关系 | 溶图 **只影响画面**。不推迟 `canAct`、不延长硬直、不改判定。逻辑该走就走、该出招就出招。 |
| 侵占禁令 | **不得侵占逻辑动画（出招锁定段 / 表 `total`）**。冻旧与溶图起点只能在逻辑已结束后的表现（含 **动画残留**）或本就允许软切的 loco 边。锁定段内默认 **不溶**。 |
| 与必接片 | **不替代** §3.7.2 站↔蹲、走路三段等 **逻辑过渡片**。有必接片时先按逻辑播片；溶图仅作表现辅助（若策略允许）。 |
| 可打断 | 更高优先级表现承诺（再攻击、受击、跳/冲等）可 **立即取消** 进行中的溶图并硬切。操作流畅优先于溶完。 |
| 实现形态 | **一套混合器**（与现走停 soft blend 同源或为其推广）；**一张分情况表** 决定是否溶、默认时长倾向。禁止「任意 clip 无表互溶」。 |

#### 3.11.2 分情况表（维护重点）

| 衔接 | 溶不溶 | 时长倾向 |
|------|--------|----------|
| 走 ↔ 停 / 走段之间 | **可溶** | **可偏长** |
| 攻击 **残留** → 移动 | **可溶** | **可稍长** |
| 攻击 **残留** → 站↔蹲过渡 | **可溶** | **可稍长** |
| 攻击 **残留** → 另一攻击 | **短或不溶** | **跟手** |
| 冲刺 **残留** → 待机 / 移动 | **可溶** | **可稍长**（次要，软化收势进 idle） |
| 攻击 / 冲刺 **逻辑锁定内** | **不溶**（不侵占） | — |
| 受击等 | **通常不溶** | 反馈清楚 |
| 跳跃落地画面 → 待机 | **可溶** | **可稍长**（逻辑落地 3f 已结束或可行动后的表现） |
| 跳跃落地画面 → 攻击 | **不溶** | **跟手** |
| 起跳 / 空中循环进出（含按下跳攻硬切进招） | **不溶** | **跟手** |
| 跳跃攻击 **残留** → 空中循环片 | **可溶**（优先：逻辑结束后 **先留攻击残留，不要立刻切回空中循环**） | **可稍长** |
| 跳跃攻击 **残留** → 落地 `land` 片 | **可溶** | **可稍长** |
| 落地画面 → 转身 | **可溶** | **可稍长** |
| 转身 → 待机 | **可溶** | **可稍长** |
| 转身 → 攻击 / 跳 | **不溶** | **跟手** |

补充约定：

- **残留 → 移动**：打断点在残留（或逻辑已结束后的可行动表现），冻的是 **打断当帧姿势**，再与走路溶；逻辑当帧已可走。
- **残留 → 站↔蹲过渡**（例：蹲轻脚逻辑结束且已松下 → 清残留 → `crouch_to_stand`；或站攻后按下 → `stand_to_crouch`）：**必接片仍要播**（§3.7.2），溶图只软化 **进过渡片第一帧** 的硬切，不替代过渡片、不侵占逻辑锁定。
- **残留 → 另一攻击**：默认 **硬切或极短**；不得为溶图牺牲出招跟手。
- **锁定段内**：即使即将 cancel，默认仍不按本表做「吃锁定」的冻旧溶图（cancel 另表，后置细化）。
- **待机/蹲 idle → 站↔蹲过渡**：姿势接近时可硬切；本表重点修 **攻击残留进过渡**。
- 具体秒数实现可配置（走停 / 残留接走 / 残留接姿态过渡 / 残留接攻 / 落地接待机）；改表意须先改本小节。
- **落地 → 待机**：冻落地当帧姿势，与待机溶；不推迟 `canAct`。
- **落地 → 攻击**（空挥落地第 2–3 帧接地面招）：硬切，不得溶。
- **跳攻残留**：空中招 `total` 结束后 **不得硬切回** `jump_*::air`。画面继续播该跳攻片（动画残留 / 定格末帧），直到落地再接到 **`land` 片**（可溶）。按下跳攻进招仍硬切。
- **落地必接 `land`**：`jump_n/f/b` 的 `land` role（`JUMP_*_LAND`）。禁止落地残留误用 `main`/`primary`（那是起跳 START）。
- **转身**：见 §3.14。落地后若要播转身，接在落地片之后（可溶）；落地已能出拳则省转身、硬切攻击。

#### 3.11.3 否决

- 用溶图 **提前结束** 逻辑 `total` 或推迟可行动。
- 全局单一时长、所有状态互溶。
- 双播旧片继续前进作为默认（本阶段固定 **冻旧**，更贴格斗跟手需求）。
- 仅靠溶图冒充站↔蹲 / 走路三段必接（残留接过渡仍须完整播过渡片）。

### 3.12 可操作 total vs 框/位移时间轴（✅ · 2026-08-12；**2026-08-13 残留规则收紧**）

> total 只管「何时又能操作」。框与位移跟 **本地框表/时间轴** 走，**不以 total 一刀切表**。  
> 与 §3.7.1 冲刺区分：冲刺 **逻辑位移不进动画残留**；出招按下表。

| 项 | 共识 |
|----|------|
| **total（公开帧表写入本地）** | **只决定何时又能操作**（走、接下招等）。 |
| **框表时间轴** | 每条框有 `from`–`to`（或等价）。**表写到哪一帧，就存在到哪一帧；表结束就结束。** 不另造「逻辑 total 自动关一切框」或「无表却挂到动画播完」。 |
| **打人框（Hit，红）** | **不残留。** 攻击段（表）一结束就关。无「伤害框残留」。 |
| **受伤框（Hurt，绿）** | **可以**在 total 之后仍存在——**仅当框表的 `to` 仍覆盖当前时间轴帧**。一般只有绿框允许这种「可操作后仍跟着表走」的情况。 |
| **推挤框（Push，黄）** | 跟 **当前姿态默认推挤** 与/或 **框表**；不单独发明长于表的残留。出招表有 push 段则按段；否则回姿态默认。 |
| **攻击附带位移** | 跟位移表/曲线长度；可长于 total。**一走路立刻打断**（选项 A）。新出招/冲/跳打断旧位移。 |
| **动画残留（glb 尾）** | 只影响 **画面** 是否继续 scrub；**不得**单独授权多开 Hit。绿框是否还在 **只看框表**，不看 glb 是否播完。 |
| **击中停顿** | 双方时间轴与位移冻结（默认）。 |

### 3.13 跳跃与跳跃攻击（✅ · 2026-08-13）

> 依据：SuperCombo Movement / Ryu；卡普空官方跳跃拳「落地后 3 帧」；对话确认「尽量靠近真游戏」。  
> 数字落盘：`action-tables/sourced-movement/ryu-movement.json`（运行时只读本地）。

#### 3.13.1 轨迹与时间（手感）

| 项 | 共识 |
|----|------|
| 隆结构 | **4 + 38 + 3**（起跳蹲地 / 空中 / 落地）。Lily/Zangief 等更长起跳不在本角色范围。 |
| 顶点 / 距离 | 高 **2.115**；前跳水平 **1.90**；后跳 **1.52**；原地跳水平 **0**。 |
| 曲线 | 公开表无逐帧速度。竖直用 `y = 4 * apex * t * (1-t)`，`t = (i+0.5)/airFrames`；空中水平匀速。审查前不得另造物理积分。 |
| 方向锁定 | 按下瞬间定前/后/原地，并锁 **世界水平方向**（`facing × 相对前/后`）。空中翻面 **不得** 把跳弧拧回去。斜跳 **不能** 改回原地跳。 |
| 原地→斜跳 | **原地跳的起跳段**（脚未离地）可改成斜跳，直到第一帧离地。 |
| 空中拳脚 | **不改轨迹**，人继续沿原弧线飞。 |
| 空中必杀改轨 | **本轮不做**（如空中龙卷改轨、OD 停空、落地 16f）。指令可先存在，行为另开。 |

#### 3.13.2 起跳段（prejump）

| 项 | 共识 |
|----|------|
| 帧数 | 隆 **4f**；`y = 0`。 |
| 投 / 被打 | 不能被投；被拳脚或弹幕打中仍算站在地上。 |
| 可改出 | **可 special cancel**（含 `2369+P` 一类容错）。 |
| 不可改出 | Drive Impact / Drive Parry；普通拳脚。 |
| 空中拳 | 起跳段 **不能** 出跳跃普攻。 |

#### 3.13.3 空中攻击

| 项 | 共识 |
|----|------|
| 飞行 | 出招 **不冻结** 水平/竖直跳弧；跳的空中时钟 **不停**。 |
| 收招 | 跳跃普攻收到 **落地为止**（公开表 Recovery = 落地后 3 帧）。空中逻辑 `total` 先走完也不恢复「再出一发」的资格。 |
| 次数 | **一跳最多一发** 空中普攻（及本轮一并锁死的空中必杀入口）。 |
| 落地砍框 | 脚沾地 **立刻关掉剩余红框**（未打完的 active 被砍）。 |
| 跳弧 vs Place | 跳弧由跳跃通道写 `x/y`。空中普攻 **不叠** 攻击 Place 作为第二份跳弧。 |

#### 3.13.4 落地 3 帧

落地长度 **一律 3 帧**（空挥与出过空中拳相同）。差别是这 3 帧里能做什么，不是多僵几帧。

| | 空挥（空中没出拳） | 空中出过拳 |
|---|---|---|
| 第 1 帧 | 什么都不能做 | 什么都不能做 |
| 第 2–3 帧 | 可接 **地面攻击 / 必杀** | 仍不能行动 |
| 防 / 蹲 / 解投 | 可以（P1 防御未接时先留接口） | **不可以**；被打为可惩罚反击态（完整 PC 标可后接，门闩本轮就要） |
| 走 / 冲 / 再跳 | 落地 3 帧内不做 | 不做 |

部分空中必杀更长落地（如空中龙卷 16f）属 §3.13.1 延后。

#### 3.13.5 表现

| 项 | 共识 |
|----|------|
| 片段 | 须接起跳 / 空中 / **落地** 三段（`jump_n/f/b` 的 prejump、air、land）。落地逻辑与残留都播 **`land`**，不得落到 START/`main`。 |
| 逻辑 vs 画面 | 逻辑落地 **3f** 后即可按 §3.13.4 行动；落地 glb 更长时走 **动画残留**（与冲刺同类），不锁操作。 |
| 跳攻收招 | 空中 `total` 完：逻辑回空中（不能再出拳），**画面留跳攻残留**；落地再溶进 `land`（§3.11.2）。 |
| 溶图 | 落地画面 → 待机 **可溶**；落地 → 攻击 **不溶**；按下跳攻 **硬切**；跳攻残留 → 空中循环 / `land` **可溶**（§3.11.2）。 |

### 3.14 转身：逻辑 / 画面朝向 / 转身片子（✅ · 2026-08-13）

> 三件事分开，禁止用「翻面」一词混称。

#### 3.14.1 逻辑转身（权威）

| 项 | 共识 |
|----|------|
| 判据 | **双方推挤黄框在左右上完全错开**（X 不再重叠）才允许重算谁在左、谁在右。 |
| 还叠着 | **不算**转身；逻辑面向保持上一帧。跳过头顶、黄框左右仍叠时如此。 |
| 越过一半 | 下落时黄框（含竖直）再叠上则 **照常推挤**，把人挤开。挤完左右不再叠，才触发逻辑转身。以挤完后的左右为准（可能仍在原侧，也可能到对侧）。 |
| 完全越过 | 黄框左右已错开 → 触发逻辑转身。 |
| 地上走过去 | 推挤在，**走不过对方**。不存在走着走到背后。 |
| 跳弧 | 仍锁世界方向（§3.13.1）。逻辑转身 **不得** 把跳拧回去。 |
| 指令 | **逻辑转身一生效，相对方向立刻按新面向算**（6=新的前方、4=新的后方；指令表、蹲/走/出招门闩都跟这个）。与模型有没有翻面无关。 |

#### 3.14.2 画面朝向（模型左右）

- 与逻辑面向 **分开存**。逻辑可以先转，模型不必同一帧翻。  
- 逻辑没转，画面绝不先翻。  
- **还在天上（落地前）**：即使已经逻辑转身，**模型朝向不变**、不播转身片。空中出拳的判定也跟模型朝向（不翻）。  
- 画面朝向只在落地之后（或人本来就在地上）按 §3.14.3 再改：播转身片或直接翻过来。

#### 3.14.3 转身片子（`TRN_STD` / `TRN_CRH`）

片子只负责好看。逻辑面向在触发当时就改完，不等片子播完（站约 70 帧、蹲约 65 帧）。

| 触发逻辑转身时在干什么 | 转身片子 |
|---|---|
| 站着 / 蹲着 | 正常播（站 `turn_std`，蹲 `turn_crh`） |
| 走着 | **不播**，身子直接翻过来，接着走 |
| 还在天上（落地前） | **不播** |
| 落地过程中才逻辑转身，落地后没出手 | 落地片后再播转身（可溶） |
| 落地已能出拳（含空挥第 2–3 帧） | **不播**；身子已是新朝向，硬切攻击 |
| 转身播到一半：走 / 跳 / 出拳 | 立刻停片 |

疲劳动画转身、空中挨打后怎么转：本条不做。

## 4. 碰撞体 · 推挤 · 防住 · 位移通道（✅；**2026-08-13 装配模型**）

### 4.1 总原则

- 权威 = **本地** 姿态/招式数据（MMDK 等转换并审查后写入）；运行时不在线抓取。
- **两层装配（必须实现）**，禁止「非出招一整块绿、出招一袋框」冒充完成：
  1. **姿态/角色身体框**：站、蹲、走等状态下的默认 **头 / 身 / 腿（绿）** 与 **推挤（黄）**；
  2. **动作衍生框**：当前招式时间轴上的 **Hit（红）**、临时 Hurt/Push 变化、位移等。
- 模型：矩形库 id + 时间段；可预烘焙。**3D 蒙皮不作对战权威**。
- 坐标：中心 + 全宽高；面向镜像（ADR-002）。逻辑单写坐标。

### 4.2 盒类型（须完整实现）

| 类型 | 颜色（调试） | 作用 |
|------|----------------|------|
| **Hit** | 红 | 打人；∩ 对方 Hurt → 击中 |
| **Hurt** | 绿 | 可被打到；**常态至少头/身/腿三块**（数据有则用数据） |
| **Push** | 黄 | 身体厚度；重叠则挤开 |

**延后（点名）**：Throw 盒精做 · 接近防精做 · Combo-only · Armor / Clash 等（见 §4.7）。

### 4.3 姿态框 vs 动作框（装配）

| 层 | 来源（数据） | 何时用 |
|----|----------------|--------|
| **姿态默认** | 如 MMDK `BAS_STD_Loop` / 蹲 loop / **`BAS_JUMP_*_AIR`** → 写入本地 **姿态框表**；站/蹲为头身腿，**空中按 MMDK 空中伤害框**（隆跳跃为空中一团身体框，不是站立三框缩短） | 待机、走路、空中、逻辑已可操作且 **不在** 招式框表覆盖中的身体 |
| **动作时间轴** | 招式 `AttackCollision` / 临时 `DamageCollision` / `PushCollision` / Place → 本地招式表 | 出招过程中按帧叠加或替换 |

**本帧世界框（须实现的合成规则）**：

1. 取 **当前姿态默认** 绿/黄（站或蹲等）；  
2. 若在出招时间轴上：再并入（或按表替换）本帧 **动作 Hurt/Push**；并入本帧 **Hit**；  
3. **Hit 仅来自动作表**，从不进入「姿态默认」；  
4. 招式框表某类在本帧无条目 → 该类不贡献动作层（身体回落到姿态默认绿/黄）。

### 4.4 随时间变化

- 每逻辑帧 0..N 个盒；多段可重叠。  
- 换招 / 硬直 / 站蹲 / 格挡 → 换集合。  
- 站→蹲：尽快切到蹲姿态框（过渡帧精修可后标，但不得长期只有一块站立整绿）。  
- 无敌 = hurt 空或 invuln。  
- 开闭长度 **只认框表**（§3.12）。

### 4.5 骨架规则

| 规则 | 说明 |
|------|------|
| **击中** | Hit ∩ 对方 Hurt（状态允许）→ 对 P2 **防住**（§4.6） |
| **推挤** | Push 重叠（左右+上下都叠）→ 水平分离。跳过头顶：飞在上方、上下不叠时挤不到；落下来又叠上则挤开。**逻辑转身只看黄框左右是否错开**（§3.14），不看中心点谁偏一点。 |
| **投** | 完整抓取 **延后**；可先播动画 |
| **调试** | 红/绿/黄可开关；须能看出头身腿（多块绿） |

同帧顺序：**先** 脚本/攻击位移 → **再** 推挤 → **再** Hit∩Hurt。

### 4.6 数据与转换

- 盒与位移 **不** 以 glTF 为权威。  
- **MMDK**：矩形库 + 招式键 + HIT 表 → 本地（§6.8）。姿态默认框从 **站/蹲等基础动作** 转换，不只从 5LP。  
- **公开帧表**：startup/active/recovery/**total**。  
- 有 MMDK 数据时：**须转换真实框进表**；不得用「一整块占位绿」当作已完成 §4.3。几何审查前可标 `placeholder`/`mmdk_converted`，但 **结构**（多块、时间段、两层）必须在。  
- 缺动画：逻辑+框仍全；表现占位 **可见标记**。

### 4.7 结算：P2 真格挡（方案甲）（✅ · 2026-08-12）

| 项 | 共识 |
|----|------|
| **P2** | **全程真格挡**。 |
| **打上** | **防住**（非干挨）。 |
| **动画** | 格挡片；**干挨分部位受击动画 → 延后**。 |
| **防御硬直 / 停顿 / 防御推开** | 须真实有；数优先 HIT/公开表。 |
| **伤害** | 可简化；停顿+硬直+推开不可省。 |

### 4.8 须完整实现的系统清单（✅ · 2026-08-13）

5. **指令表应接招式**：均可出逻辑；框数据来自转换或审查表；缺动画有可见占位。
