## 1. 输入机制（✅）

### 1.1 操作体系

- **仅 Classic**（6 键 + 8 向）。
- **不实现 Modern**。
- 默认输入设备：**键盘**；手柄可扩展，语义与 Classic 相同。

### 1.2 每逻辑帧

- 逻辑 **60 Hz** 采样一次（与 ADR-001 一致）。
- 每帧记录：
  - 方向（numpad **1–9**，相对**当前面向**）
  - 六键按下 / 持续 / 松开（实现可简化，但语义上区分边沿与按住）
- 输入先进入缓冲 / 历史，再由状态机决定是否消费。

### 1.3 指令意图类别

识别器应能产生（或预留）以下意图类型：

| 意图类型 | 示例 |
|----------|------|
| 移动 | 走、蹲、跳、66 / 44 dash |
| 普攻 | 5 / 2 / j. + LP…HK |
| 指令普攻 / TC | 6MP、4HP、HP~HK 等 |
| 必杀 / OD | 236P、623PP 等 |
| 超必杀 | 236236P 等 |
| 投技 | LP+LK / 4+LP+LK |
| Drive | DI、Parry、DR、Reversal（可占位，**接口预留**） |

### 1.4 指令识别原则

- **方向历史 + 按钮** 匹配 special / super（步间间隙见 §2）。
- **Dash** 用独立规则，不与 special 混成同一套匹配器。
- **同帧多意图** 用**固定优先级表**裁决；禁止隐式「谁先处理谁赢」。
- 面向翻转时，左右方向与盒一并镜像。

### 1.5 同帧优先级（初表，可后改）

从高到低：

1. Super（资源与状态允许时）
2. Special / OD
3. Throw
4. Drive 系统技（DI / Parry / DR 等，按当前状态是否合法）
5. Target Combo / Chain 后续
6. Normal
7. Dash / Jump / Walk / Crouch

**命中解析**（与输入优先级分开）：

- 同帧 **strike > throw**
- 无无敌时双方 hit → **trade**

## 2. 预输入 / 缓冲（✅）

### 2.1 总原则

- **要做预输入**（对齐 SF6 input buffer 语义）。
- 工程上拆成 **三层**：

| 层 | 作用 |
|----|------|
| **A. Action buffer** | 不可行动期登记下一意图，可行动时执行 |
| **B. Motion history** | 方向序列历史，供 special / super 匹配 |
| **C. Cancel 窗消费** | cancel 窗内合法意图打断当前招 |

### 2.2 默认数值（可配置）

| 配置项 | 默认 | 含义 |
|--------|------|------|
| 标准行动预输入 | **4f** | 多数 link / 硬直结束出招等 |
| Dash / 起身类更宽缓冲 | **7f** | dash、部分 wakeup 相关 |
| 起身 reversal 与 7f 冲突时 | **进配置表审查**，不散落硬编码 | 公开资料口径可能不一致 |
| 指令步间最大间隙 | **约 9f**（可按招覆盖） | 初值 |
| Dash 方向 / 中性上限 | 各 **8f** | 对齐公开 Movement 整理 |

改手感优先改配置 / 表，不改状态机主路径。

### 2.3 行为规则

- recovery / hitstun / blockstun / landing 等**锁定期**可写入 action buffer。
- 进入**可行动**的第一帧按 §1.5 优先级消费 buffer。
- **Hitstop** 期间：位移 / 招式帧可停，**仍须接受** cancel / buffer 输入。
- 存在「必须晚 cancel」的连段：支持不被「尽早 buffer」破坏的策略。
- 已知例外 → **例外表**，不散落 if。

### 2.4 分期

| 项 | 共识 |
|----|------|
| 标准 4f + motion 历史 + cancel 消费 | **第一期必做** |
| Dash 7f / 起身更宽（默认 7） | **第一期做** |
| Screen freeze / DR 冻结与 buffer 相位 | **可后置**；差异登记可见 |

## 3. 动画 / 逻辑状态机与打断（✅）

### 3.1 总原则

- **规则权威 = 逻辑状态 + 本地帧表 / cancel 标志**，不是 3D clip 长度或 Animation Event。
- 动画是**表现层**：跟随 `moveId + localFrame`（可 cross-fade），不反向定义规则。
- 服从总共识 **R2**：不符理想行为时改本地表再贴动画。

### 3.2 必须建模的逻辑状态族

| 族 | 要点 |
|----|------|
| Neutral | stand / crouch / walk；面向 |
| Attack | startup / active / recovery；`localFrame` |
| Stun | hitstun / blockstun；可带 CH/PC 修饰 |
| Knockdown / Wakeup | 倒地、起身（细则可分期） |
| Jump | prejump → airborne → landing recovery |
| Dash | forward / back |
| Throw | startup / active / whiff / tech 结算 |
| Special / Super | 与 Attack 同形或子类；资源消耗 |
| Drive* | Parry / DI / DR / Reversal 等（**可占位**，接口预留） |

### 3.3 招式阶段

- **Startup / Active / Recovery**；startup 计数与项目帧索引约定一致（含 FAF / 第一 active）。
- 命中进入 **hitstop**；输入按 §2 处理。

### 3.4 可打断矩阵（逻辑）

| 当前 | 可被什么打断 | 条件 |
|------|----------------|------|
| Attack（cancel 窗内） | Sp / SA / DI / DR / TC·Chn / Jmp（若表允许） | **逐招表 + 当前帧** |
| Attack（窗外或无旗） | 仅受击或自然结束 | — |
| Hitstun / Blockstun | 一般不可主动出招；可 buffer 至结束 | 系统技按表 |
| Prejump | 可 special cancel；不可 DI/Parry | 帧数进表（多数 4f） |
| Dash | 前 dash 前段可进 Parry 等（按表） | 其余高度锁定 |
| Landing | 按落地规则分帧可行动 | 细则可分期 |
| 动画 clip | **永不**单独授权打断 | 只跟逻辑 |

### 3.5 Cancel 表

- **按招、按帧 / 区间**；禁止「只要 active 就能全 cancel」。
- 能表达公开表常见语义：**C / Sp / SA / Chn / TC / Jmp** 等。
- 调试 H2：状态名、localFrame、是否在 cancel 窗。

### 3.6 与动画边界

- 逻辑切状态 → 表现切 clip。
- 开 / 关 hitbox **以逻辑帧为准**。
- 视觉可插值；**判定与调试框以逻辑为准**。

### 3.7 逻辑帧如何带动画面（✅ · 2026-08-11）

> 对话确认：游戏 **60 格/秒** 与出招画面 **逐格对应**；不以动画文件自己播完为准。

| 原则 | 共识 |
|------|------|
| 时间权威 | **逻辑 60 Hz**（ADR-001）。出招 / 有限时长状态：当前是第几格，就显示该格对应姿势。 |
| 出招总长 | 以**本地招式表**的总帧 / startup·active·recovery 为准；数字**对齐公开帧数据**后再写入本地（总共识 R2）。 |
| 与动画文件 | 文件时长可以长于或短于逻辑总帧。**收招、回待机、cancel 窗只看逻辑**，不看 glb 是否播完。 |
| 画面取样 | 每一逻辑帧对应一帧画面进度（「一格一格跟」）。若源 clip 采样数与逻辑 total 不一致：实现可选 **截断** 或 **在总帧内均匀取姿势**；不得改为「clip 播完才结束逻辑」。 |
| 待机 | 允许动画 **自由循环**（不强制与某一出招表 total 对齐）。 |
| 多段动作 | 走路 / 跳跃等按**逻辑阶段**切换片段（如起步→循环→结束；起跳→空中→落地）；**每一段内**仍用本段逻辑帧推进画面。 |
| 官方文档 | Capcom **无**公开的「逻辑帧↔引擎动画 API」规范。工程依据：公开帧数据（时间语义）+ 本文件 + ADR；社区引擎文档（如 MUGEN AIR 的 game-tick）仅作结构参考。 |

**否决**：以 3D clip 长度或 mixer 自然播完作为出招 / 状态结束条件。

### 3.8 动画映射范围（当前阶段）（✅ · 2026-08-11）

> 解决「只有指令→动画的粗映射、跳/投等未接上」：以已有逻辑→资源映射表为主，先把当前阶段要用的状态接进运行时。

| 项 | 共识 |
|----|------|
| 策略 | **接上已有映射**：`action-tables` / `ryu-logic-to-glb-map`（及运行时等价表）中已标可用的条目，逻辑状态必须能进、且能播到正确片段（含多 role 时按阶段选片）。 |
| 当前阶段必接 | **跳跃**（含前/后/中性所需片段）、**投技（表现）**、**走路（起步 / 循环 / 结束三段）**。 |
| 投技深度 | 当前阶段 **先能播投技动作**；抓取成功 / tech 结算等可后置（状态接口仍按 §3.2 Throw 预留）。 |
| 明确后置 | **超必杀**及映射表中已标延后项（如部分指令重脚等）**不**阻塞当前阶段。 |
| 缺资源时 | 优先补接线与预加载；仅当映射/文件确实缺失时才允许占位表现，并在表中可见标记。 |

### 3.9 脚部（✅ · 2026-08-11）

| 项 | 共识 |
|----|------|
| **出招支撑脚** | **要做**：出招（尤其踢类）支撑脚在着地期间应稳定，**不得**相对地面无故滑动。 |
| **走路** | **不做**支撑脚锁定。走路靠 **移动参数（逻辑速度/距离）+ 动画播放（含三段与播放速率调整）** 对齐观感。 |
| **待机** | **不做**支撑脚锁定。 |
| **待机脚抖** | **要处理**：禁止（或不得依赖）「每帧把最低的一只脚死贴地面」这类导致左右交替上下抖的修正；待机可在换片时校正或平滑处理。 |
| **与位移关系** | 角色水平位置以 **逻辑位移** 为准；支撑脚锁定是表现层在「脚应钉住」时的约束，不得与逻辑位移双计导致搓地。 |

### 3.10 走 / 冲 / 跳距离与攻击附带位移（✅ · 2026-08-11）

| 项 | 共识 |
|----|------|
| **走、冲、跳** | 速度、距离、持续帧等 **采用社区/wiki 等公开整理数据**（如 SuperCombo Movement / 角色 Data），写入本地后运行时只读本地（见 §6.7）。 |
| **攻击自身位移** | 公开帧表通常 **不提供** 逐帧「自己挪多少」。做法：从 **现有动画** 估计自身水平位移，再人工调整；写入本地招式/状态数据。轻拳等站桩招可为 0；扫腿等可有非零曲线。 |
| **与打中推开** | **自身位移** 与 **命中/防御后的推开（对方或双方）** 分字段、分通道，禁止混成一个数无法审查。 |
| **单写者** | 逻辑坐标 `x`（等）只由逻辑侧更新。若动画含水平 root，用于 **估计表** 或 **已 baked 进逻辑表** 后，表现不得再叠第二份水平位移。 |
| **单位** | 与走路等系统移动使用 **同一套逻辑世界单位**（再经 worldScale 进表现）。 |

## 4. 碰撞体（✅）

### 4.1 总原则

- 权威 = **本地逐逻辑帧盒数据**（`moveId + localFrame`）。
- **3D 蒙皮不作对战权威**；骨点仅可辅助填表。
- 坐标：**中心 + 全宽高**；面向镜像（ADR-002）。

### 4.2 盒类型

**第一期必做**：Hit · Hurt · Push  

**分期 / 接口预留**：Throw hit / Throw hurt · Proximity · Combo-only hit · Unique / Armor / Clash 等  

### 4.3 随逻辑帧变化

- 每帧 0..N 个各类型盒。
- 换招 / 硬直 / 站蹲 → 换盒集合。
- 站→蹲 hurt 过渡（公开约第 5 帧满变）：**登记为应对齐**；第一期可简化为立即变蹲盒。
- 无敌 = hurt 缺失或 invuln 标志（schema 实现时定）。

### 4.4 骨架规则

- Strike：active Hit ∩ 对方 Hurt（状态允许）。
- Push：重叠则分离。
- 投：Throw 盒相交（状态允许）；同帧 strike 优先（§1.5）。
- H2：至少 hit（红）/ hurt（绿）；建议 push。

### 4.5 与帧表

- 盒挂在招式 / 状态帧数据上，不挂 glTF 动画轨道。
- 允许占位大盒；「已复刻」前须审查。

## 6. 必须参考的动作表（✅）

### 6.1 原则

- 填本地帧表 / 指令表时必须对照权威源。  
- **运行时只读本地表**；站际冲突 → 审查后写入本地为唯一权威（总共识 R2）。  
- **本地落盘目录**（独立维护）：

```
docs/character-control/action-tables/
```

### 6.2 权威源清单

完整列表与链接见：

- `action-tables/sources.md`

摘要：SuperCombo 系统页（Game Data / Offense / Defense / Movement / Gauges / Controls）+ 隆 Ryu / Data / Combos + 官方 Command List / Frame Data + UFD 交叉 + Hitbox Viewer 对照。

### 6.3 记法

见 `action-tables/notation.md`（`>` cancel · `~` chain · `,` link · numpad）。

### 6.4 本地表最低字段

见 `action-tables/schema-move-table.md`。

### 6.5 隆 Classic 指令对照

见 `action-tables/ryu-command-list-classic.md`。

### 6.6 样板

- **5LP** 为第一条按完整标准打通的样板（总共识）：验证采信 → 本地表 → 输入 / 缓冲 → 状态机 → 盒 → 表现。

### 6.7 公开数据必须落本地（✅ · 2026-08-11）

> 与 §3.10 配套：凡实现所依赖的公开数字与出处，不得只留在浏览器书签或口头约定。

| 要求 | 说明 |
|------|------|
| **落盘位置** | `docs/character-control/action-tables/`（或该目录下子路径）；机器可读配置可同步到 `app/public/data/` 等运行时路径，但 **人读出处与审查记录以 action-tables 为准**。 |
| **至少收录** | 隆（及当前角色）的 **前/后走速度**、**前/后冲距离与帧数**、**跳跃时间结构与距离/高度**（公开表有则录）；来源 URL、检索/采信日期、与本地单位换算说明。 |
| **攻击帧数据** | 继续按 §6.1–6.4：startup/active/recovery 等写入本地招式表；与位移字段分开。 |
| **攻击自身位移** | 无完整公开逐帧表时：记录 **估计方法**（如从哪条动画、如何抽样）与调整备注；数值进本地招式/状态表。 |
| **运行时** | 只读本地；网上源变更时先改本地并审查，不在线抓取当权威。 |
