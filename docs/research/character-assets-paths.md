# 角色素材路径调研（草案）

> 关联共识：单角色深度、帧数据复刻一招、中文私有仓库、WebGPU/Three。  
> 问题：SF6 极度依赖动作；素材从哪来？逻辑是否必须绑定官方动画？

---

## 1. 先澄清一个关键误解

「街霸底层逻辑与画面动作密不可分」——**在产品体验上对，在工程实现上可以拆开**。

| 层 | 真正绑定的是什么 | 是否必须官方模型 |
|----|------------------|------------------|
| 规则层 | startup / active / recovery、cancel、伤害、硬直 | **否**（纯数字表） |
| 判定层 | 第 N 帧 hitbox/hurtbox 的位置与尺寸 | **否**（可用骨点或抽象盒；盒可手 key） |
| 表现层 | 骨骼动画、特效、音效、镜头 | 想「像」才需要高质量动作 |
| 手感层 | 位移（root motion 或脚本位移）、受击反应 | 需要**时长与位移曲线**对齐，不一定要官方 mesh |

因此有三条完全不同的目标，**不要混成一个「找素材」问题**：

1. **学规则**：公开帧数据 + Dummy 几何体即可。  
2. **学手感/镜头**：需要「时长正确 + 位移大致正确」的动画，mesh 可替身。  
3. **学外形还原**：才需要接近官方的模型与动画剪辑——法律与工程成本最高。

共识里「严格复刻一招」默认落在 **1 + 部分 2**；「尽可能还原角色动作」若指 **3**，必须单独决策风险。

## 2. 素材路径总表

### 路径 A — 从正版 SF6 提取（RE Engine 生态）

**做法概要**

- 社区存在 RE Engine 相关工具链（如 RE Asset 类提取、Blender 的 RE-Mesh 插件等），用于 **mod / 私人预览** 较常见。  
- 目标物通常包括：mesh、骨骼、部分动画片段、贴图。  
- 导出后再进 Blender → glTF → Three.js。

**优点**

- 动作、比例、节奏 **最像** SF6。  
- 单角色「只做一个」时，投入产出在「还原」维度最高。

**缺点 / 风险**

- **著作权**：角色模型、动画、贴图均为 Capcom 资产；**提取本身**多落在 EULA/版权灰黑区；**再分发、上传仓库、公开 demo、挂网站** 风险明确升高。  
- 工程脏：骨骼命名、缩放、坐标系、动画压缩、IK/辅助骨、布料与 RE 专有通道在 Three 中 **大量丢信息**。  
- 动画片段与 **训练模式帧数据** 未必 1:1 可直接当逻辑时钟（表现帧 vs 逻辑帧、混合、取消过渡）。  
- 版本更新、加密/打包变更会导致工具链反复坏掉。

**建议定位**

- 仅当你接受：**纯本机、不进 git、不公开** 的「动画示波器」实验。  
- **不要**作为默认可开源/可演示主路径。  
- 即便私人用，也建议逻辑层仍用 **自有帧表**，官方动画只做 scrub 对齐，避免「动画文件即法律绑定 + 逻辑绑定」双重耦合。

---

### 路径 B — 下载他人已 rip 的模型站（Open3DLab 等）

**优点**：省去自己解包。  
**缺点**：版权问题 **更糟**（传播盗版资产）；来源不明、绑骨质量参差；同样不能进公开项目。  
**建议**：**不推荐**作为本项目路径。

---

### 路径 C — 官方/授权渠道

SF6 **没有**面向个人开发者的「角色 glTF 授权包」或官方 SDK 角色库（电竞社区许可也不等于可把资产嵌进你的 Web demo）。  
周边手办扫描、官方 CG 也不能当游戏运行时资产。  
**结论**：正版可玩参考 ≠ 正版可嵌资产。

---

### 路径 D — 买/下免费「格斗向」通用资产（合法主路径之一）

来源示例（类别，非背书某一店）：

- 商店：Unity/Unreal Marketplace、Gumroad、CGTrader 等 **明确授权用于游戏** 的格斗动画包、武士/拳手角色。  
- 免费：部分 CC0 角色 + 自备动画。

**优点**：可商用条款清晰（需读 license）；可进仓库（若许可允许）。  
**缺点**：气质是「泛格斗」不是「SF6 某角色」；仍要自己剪成 startup/active/recovery 分段。

---

### 路径 E — Mixamo / 自动绑骨 + 库动画

**优点**：快、合法（遵守 Adobe Mixamo 条款）、适合占位。  
**缺点**：动作偏通用、打击感与取消节奏 **很难** 像街霸；库动画难拆成严谨帧窗。  
**建议**：仅作 **管线冒烟**（glTF 进 Three + 播放），不作为「还原 SF6」终局。

---

### 路径 F — 自制/委托关键帧动画（Cascadeur、Blender、动捕）

**做法**

- 参考：**自己录的** 训练模式视频（或公开赛事录像作学习参考）→ 数帧 → 在 Cascadeur/Blender 里 **重做** 同长度动作。  
- 单角色、先 5～15 个状态：待机、走、蹲、L/M/H、受击、防御。

**优点**

- 版权清晰（你的表演/你的关键帧）。  
- 可 **故意** 做成与公开帧数据同长，完美服务「复刻一招」。  
- 与逻辑事件轨（hitbox on/off）可在 DCC 或引擎里对齐。

**缺点**

- 质量依赖动画功力；想达到 SF6 制作水准成本极高。  
- 但 **demo 阈值** 往往「帧对 + 意图对」就够，不需要电影级。

---

### 路径 G — 视频/动捕重定向（不直接用官方文件）

- 工具链：手机拍 / 已有 cap、Rokoko、Move.ai、Cascadeur 清理 → 重定向到自有骨骼。  
- 或：从 **自己游玩录像** 做 rotoscope 式关键帧（费时）。

**优点**：可学「韵律」且不复制二进制资产。  
**注意**：若输出结果 **高度可识别为某受保护角色形象+标志性招式表演**，外形设计仍可能有形象权/商标问题；用 **原创角色皮** 可大幅降低风险。

---

### 路径 H — 无全身动画：程序/分层表现

- 身体：胶囊 + 手臂 IK/简单 swing 曲线。  
- 打击感：闪白、顿帧、残影、音效、镜头震动、命中停（hitstop）。  
- 格斗游戏 **可读性** 很大程度来自这些，而非面部微表情。

**优点**：最快验证帧数据训练场。  
**缺点**：观感离 SF6 宣传片最远；但与共识「训练场优先」一致。

---

### 路径 I — 混合策略（最推荐作为工程默认）

```text
逻辑与框体     ← 公开帧数据 / 自研表（可声称「参考角色 X 的 5LP 时序」）
表现动画 v0    ← 胶囊 或 合法商店/自制短动画（同帧长）
表现动画 v1    ← 自制/购买高质量动作，仍同帧长
（可选私人）   ← 本机官方提取动画仅作「对齐示波器」，永不入库
```

这样：**还原的是时序与结构**，不是「把 RE 资源搬进 Web」。

## 3. 技术现实：官方动画进 Three/WebGPU 仍很难「开箱即还原」

即使私人提取成功，常见坑：

1. **T-Pose/A-Pose、单位（cm/m）、Y-up** 转换。  
2. **辅助骨、缩放骨、物理骨** Three 不跑 RE 物理。  
3. **动画是片段库 + 运行时混合**，不是一个 FBX 含全 moveset。  
4. **逻辑不该读动画当前时间当唯一真相**（网络/顿帧/暂停时更明显）；动画应 **跟随** 逻辑帧或与逻辑共享同一 clock。  
5. glTF 对 morph/复杂材质/多 UV 的损失。

因此：「拿到官方动画 = demo 就很像」是 **高估**；「对齐一招的帧时钟 + 自有/合法动画」是 **低估难度但可交付**。

## 4. 与「只做一个角色」的匹配度

| 路径 | 单角色深度 | 像 SF6 动作 | 合法可维护 | 近两周调研期是否值得深挖 |
|------|------------|-------------|------------|---------------------------|
| A 提取 | 极高 | 极高 | 差（私有限定） | 仅作风险知情，不当默认 |
| B 下站 | 高 | 高 | 很差 | 否 |
| D 购买 | 中高 | 中（泛格斗） | 好 | 值得列候选店与授权 |
| E Mixamo | 低 | 低 | 好 | 仅管线冒烟 |
| F 自制关键帧 | 高（可控） | 中→高 | 最好 | **强烈建议作为主方案** |
| H 程序化 | 中（规则） | 低 | 最好 | **训练场 M0 默认** |
| I 混合 | 可演进 | 可演进 | 好 | **架构默认** |

## 6. 临时结论（调研建议，非最终产品决议）

- **仓库默认资产**：路径 **H → F/D**，逻辑与帧表独立。  
- **「严格复刻一招」**：不依赖官方 mesh；依赖公开帧表 + 等长动画（自制或购买）。  
- **路径 A**：最多定义为 *可选的私人对齐工具*，与 git 隔离（如 `private/ref/` + gitignore），不写进构建产物。  
- 单角色策略 **正确**：动作集合可控；但应把预算花在 **状态覆盖与帧对齐工具**，而不是第一天解 RE 包。
